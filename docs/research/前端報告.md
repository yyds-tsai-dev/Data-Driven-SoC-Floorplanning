# ICCAD 2026 Problem C — 前端方法報告

一份給外部交換用的說明，涵蓋我們的前端（擴散模型）如何運作、實測到什麼、
以及哪些方向已經被我們自己的量測否定。所有數字都是 official100 上的實測值。

---

## 1. 一句話總結

前端是一個**擴散模型**，一次生成整張版圖的座標與長寬比；它的幾何品質已經非常
接近黃金解（面積誤差 `0.0013`、利用率 `96.7%`），**但它不產生合法解**——輸出
帶有約 `3.2%` 的重疊面積。前端不是我們的瓶頸。

---

## 2. 問題表述

把 21–120 個 block 放進版圖，最小化面積與線長，滿足固定形狀、預置位置、
MIB 群組、叢集、邊界五類約束，且不可重疊。

官方成本：

```
Cost = (1 + 0.5·(HPWL_gap + Area_gap)) × exp(2·V_rel) × max(0.7, (t/中位數)^0.3)
總分 = 各 case 加權平均，權重 exp((blocks − max_blocks)/12)
```

權重高度集中：**前 10 個 case 佔 57%、前 20 個佔 81%**。任何硬約束違反
（重疊、面積超差、固定／預置被移動）直接判 `M = 10`。

> **注意**：官方評估腳本把 `RuntimeFactor` 硬編成 `1.0`（本地看不到跨隊伍中位數）。
> 這會讓時間看起來免費。實際上它是乘在整個成本上的，我們一度因此把管線調錯方向。

---

## 3. 表示法：每個 block 只有 3 個數字

擴散在一個 `[N, 3]` 的狀態上進行，每個 block 是：

```
(中心 x, 中心 y, log 長寬比)
```

寬高**不是**預測出來的，而是由題目給的面積解析算出：

```
width  = √(area · aspect)
height = √(area / aspect)
```

**這是我們認為最值得分享的一個設計決定**：面積約束因此天生精確滿足，
不需要任何後處理或懲罰項。固定形狀與預置 block 的尺寸在解碼後直接覆蓋回去，
`log aspect` 被裁切在 `±log 3` 以內。

座標以 `√(Σ area)` 正規化，狀態再以資料集的 mean/std 標準化。

---

## 4. 條件輸入

模型不只看噪聲狀態，還吃兩類條件：

**每個 block 的 34 維靜態特徵**，包含

| 欄位 | 內容 |
| --- | --- |
| 0–2 | 面積（對數相對值、平方根、block 數比例） |
| 3–6 | 固定 / 預置 / MIB 成員 / 群組成員 |
| 7–10 | 四個邊界位元（左右上下）分開成 4 個特徵 |
| 11–12 | 所屬群組 / MIB 的大小 |
| 13–14 | 連線度數與加權度數（取對數正規化） |
| 15–25 | pin 相關特徵 |
| 26–29 | 已知的座標與尺寸（預置／固定才非零） |
| 30–33 | 全域 pin 的包絡範圍 |

**三張鄰接矩陣**：連線圖（b2b）、群組圖、MIB 圖。

---

## 5. 網路：全域注意力 + 分型別圖傳遞

`GraphAttentionBlock` 每層做三件事：

1. **全域自注意力**（`MultiheadAttention`，以 `node_mask` 遮蔽 padding）
2. **分型別圖訊息傳遞**——把 `[自身, A_conn·h, A_group·h, A_mib·h]` 串接後過 MLP
3. 標準前饋層

三種關係各自獨立傳遞，而不是混成一張圖。這是我們刻意的選擇：群組與 MIB 的語意
和連線完全不同。

刻意**沒有**使用 PyG 之類的外部圖框架，只用原生 PyTorch——為了讓提交時的環境
與打包盡量簡單。

時間步以 sinusoidal embedding 注入。

**目前尺寸**：`hidden 512 / 10 層 / 8 heads`，58.6M 參數。

---

## 6. 訓練

資料是 FloorSet 的黃金版圖（約 100 萬張）。損失是多項加權：

| 項 | 權重 | 說明 |
| --- | ---: | --- |
| noise MSE | 1.0 | 標準擴散目標 |
| x0 | 0.10 | 對乾淨狀態的直接監督 |
| topology | 0.05 | 相對位置關係 |
| bbox | 0.50 | 外框面積 |
| contact | 0.20 | 邊接觸 |
| overlap | 0.05 | **實際關閉**（見下） |

幾何類的項有 warmup（1000 步）與 ramp（4000 步）。

訓練設定：1000 個擴散時間步、AdamW、cosine 排程 `3e-4 → 3e-5`、
EMA `0.9999`、有效 batch 256、200,000 步。

### 6.1 訓練久非常有效，而且是我們最大的兩個增益

| 訓練長度 | official100 品質 |
| --- | ---: |
| 12,000 步（起點） | 1.3943 |
| 100,000 步 | 1.3322 |
| 200,000 步 | 1.2523 |

兩段都通過 bootstrap 檢定（99.8% / 100%）。**如果只能給一個建議，就是訓練得比
你以為需要的更久。**

### 6.2 訓練是 dataloader 綁死的，不是 compute 綁死的

| 配置 | 參數量 | samples/s |
| --- | ---: | ---: |
| hidden 192 / 6 層 | 5.0M | 836 |
| hidden 384 / 8 層 | 26.5M | 833 |
| hidden 512 / 10 層 | 58.6M | 816 |

**參數量 11.7 倍，吞吐只掉 2.4%。** 另外 `workers=4` 比 `workers=1` 快 55%，
而 step 60 的 loss 逐位元相同。如果你的訓練也是這個形狀，放大模型幾乎免費。

（到 157.8M 才變成 compute-bound，吞吐掉到 722 samples/s。）

## 7. 取樣：15 步 DDIM + 引導 + 硬投影

### 7.1 步數

15 步。我們用五個種子在 official100 上比較過 15 / 25 / 50 / 100，**15 步同時
更快且品質更好**。

### 7.2 引導

在最後幾步對預測的乾淨狀態 `x₀` 做**有界的正規化梯度步**，目標包含群組連通性、
邊界、重疊等軟項。步長 `0.02`、衰減 `0.5`、只作用在自由變數上（已知的預置／固定
座標被遮蔽）。

我們同時跑 4 個引導設定產生候選，用一個便宜的代理成本挑一個。

### 7.3 FlowPlace 式硬投影（最後 4 步）

這是前端與後端的真正接縫，也是我們認為最值得討論的一段。

DDIM 每一步模型會預測一個 `x₀`（它認為的最終版圖），但那個 `x₀` **有重疊**。
投影在中間攔截：

```
模型預測 x₀（有重疊）
   ↓  用便宜的合法化器消除重疊
x₀_legal
   ↓  重算噪聲 noise = (state − √α·x₀_legal) / √(1−α)
剩下的去噪步驟改朝「合法的那個點」走
```

- 只在最後 4 步做（更早做沒意義，`x₀` 還太模糊）
- 投影用的合法化器刻意便宜，因為每個 case 要跑約 60 次
- **前 3 次是導引**（結果丟棄，只用來改變軌跡）；**最後 1 次的結果就是交給後端的版圖**

## 8. 前端的實測品質

用純模型輸出（不經投影、不經後端）在 official100 上量：

| 模型 | 訓練步數 | 重疊對數 | 重疊面積 | area gap | hpwl gap |
| --- | ---: | ---: | ---: | ---: | ---: |
| 5.03M | 12,000 | 8,513 | 234,929 | 0.0066 | 0.0021 |
| 5.03M | 200,000 | 7,395 | 83,375 | 0.0075 | −0.0006 |
| 58.6M | 200,000 | 7,433 | 54,272 | 0.0039 | −0.0012 |
| 157.8M | 200,000 | 7,794 | **46,922** | **0.0021** | −0.0009 |

**利用率 96.7%，黃金解是 97.1%。** 線長比基準還好（gap 為負）。

### 一個機制發現

**訓練讓重疊變「淺」而不是變「少」。** 重疊對數幾乎不動（8,513 → 7,395，−13%），
重疊面積卻崩掉（234,929 → 46,922，−80%）。淺的重疊只需要小位移就能分開，
這解釋了為什麼訓練久這麼有效。

## 9. 我們試過並被自己的量測否定的方向

這一節可能比前面更有用。

### 9.1 訓練期加入 overlap loss —— 無效

`overlap_weight` 我們實作了但**保持關閉**。它的梯度把 block 往**任意方向**推開，
而重建損失把它們推向**正確位置**——兩者直接對抗。而且黃金版圖本來就沒有重疊，
所以準確的重建**自然就會**讓重疊變淺，不需要額外的項。

### 9.2 繼續放大模型 —— 無效

157.8M 的前端指標**每一項都更好**（重疊面積再降 13.5%、area gap 0.0021），
端到端分數卻**沒有改善**（+0.0096，P=35%）。

原因是後端的輸出幾乎與它收到什麼無關。我們另外量過：把交付給後端的版圖品質
改善 21%，最終分數只動 `−0.0002`。

**前端不是瓶頸。**

### 9.3 各種前端指標作為預測子 —— 部分有效、最後失效

- **前端 area gap 不預測分數**：某個 checkpoint 的 area gap 更好卻輸了 0.0088
- **重疊面積曾經是好的預測子**，跨三個 checkpoint 單調有效
- **但它最終也失效**：157.8M 的加權重疊面積好 21.3%，分數不動

我們的結論是：重疊面積只在**前端還是綁定約束時**才預測分數，而前端已經不是了。

---

## 10. 給交換對象的三個要點

1. **面積約束從表示法消除掉。** 只預測位置與長寬比，寬高由面積解析算出。
   這比事後修正或加懲罰項乾淨得多。

2. **訓練長度的報酬遠超過模型容量。** 12k → 200k 步值 `−0.14` 的品質；
   5M → 58.6M 的容量提升在統計上無法確認。而且如果你的訓練是 dataloader-bound，
   先修 dataloader 再考慮放大模型。

3. **投影的接縫值得仔細設計。** 我們的前端交出 96.7% 利用率的版圖，
   而消除那 3.2% 重疊的過程讓利用率掉到 78%——**這是我們目前最大的損失來源**，
   而它發生在前端與後端的交界，不在任何一邊的內部。
