# ICCAD 2026 Problem C — 後端方法報告

一份給外部交換用的說明，涵蓋我們的後端如何把模型候選轉成合法解、如何在固定
時間內分配候選與選解、實測到什麼，以及哪些方向已被我們自己的量測否定。除非
另外註明，最終數字都來自提交包解壓後的 official100 full evaluation。

---

## 1. 一句話總結

後端不是一個單獨的「去重疊器」，而是一個**固定時限、合法性優先的候選組合**：
column-slicing 的多重啟動、direct diffusion 與 flow matching 同時供給候選，每個
學習式候選都要經過同一套合法化與精修，最後才用接近官方形式的代理成本與保守
切換門檻選解。

最終提交包在 official100 上達到 **`1.1437` no-runtime、100/100 hard feasible、
平均 `0.299 s/case`**。按官方 case 權重重算，HPWL gap、area gap 與相對軟違規
分別約為 `0.114`、`0.049`、`0.027`；後端目前最大的剩餘缺口已從「能否合法化」
轉成「能否在不破壞合法拓撲下縮短線長」。

---

## 2. 後端的任務邊界

後端接收 21–120 個 block 的面積、block-to-block 與 pin-to-block 連線、pin 座標、
固定／預置資訊、MIB、群組與四向邊界條件，輸出每個 block 的
`(x, y, width, height)`。

它同時面對四種不同性質的要求：

| 類別 | 要求 | 後端處理方式 |
| --- | --- | --- |
| hard | 不重疊、soft block 面積容差、fixed 尺寸、preplaced 位置與尺寸 | 候選准入前必須滿足；失敗時不用品質分數交換 |
| soft | boundary、grouping、MIB | 納入代理成本的指數項，並由末端外科修復處理 |
| quality | HPWL、bounding-box area | 在合法候選之間比較 |
| runtime | 相對其他隊伍的 case runtime | 用 block count 決定本地時間配置，但不在本地假裝知道官方中位數 |

官方的 no-runtime 部分可寫成：

```text
C_nr = (1 + 0.5·(max(0, HPWL_gap) + max(0, Area_gap))) × exp(2·V_rel)
```

任何 hard constraint 違反都直接得到固定懲罰 `10`。這決定了我們的順序：先讓候選
進入合法可行域，再談 HPWL、面積與軟違規；不是把重疊當成另一個可交換的 loss。

---

## 3. 一個表示法，三種硬度

後端內部統一使用 `[N, 4]` 的矩形陣列，但依約束把 block 分成三種：

| kind | 對應 block | 可變量 |
| ---: | --- | --- |
| 0 | soft | 位置與長寬比可變；面積由 `width × height` 維持 |
| 1 | fixed shape | 位置可變，`width/height` 不可變 |
| 2 | preplaced / locked | `x/y/width/height` 全部不可變 |

MIB 群組若包含 hard-shape 成員，其餘成員直接繼承同一組尺寸；全為 soft 的 MIB
群組則在同一 column unit 中共同決定形狀。Grouping 與 MIB 的可移動成員再以 DSU
合併成 placement units，unit 內保存群組連續性、上下邊界需求與左右牆需求。

這個表示法的作用不是讓約束「容易懲罰」，而是讓一部分約束在搜索中保持不變：
preplaced 保持位置與尺寸、fixed shape 保持尺寸、soft block 的形狀由目標面積與
可用帶寬解析決定。後處理只有在官方允許的 1% soft-area 容差內，才會使用極少量
面積 slack 把整條 packed chain 壓回可達的邊界線。

## 4. 模型候選是供給，不是答案

後端同時保留三種候選來源：

1. **Column arm**：從 pin／graph-weighted centroid 建立便宜的相對位置種子，再直接
   進 column-slicing 搜索。
2. **Direct arm**：模型一次預測整張版圖；提交操作點用 2-step
   DPM-Solver++(2M) 產生候選。
3. **Flow arm**：以 8-step Euler flow matching 補另一個生成分布，並用 antithetic
   noise 增加批次內多樣性。

模型輸出不會直接交給 evaluator。GPU 在 CPU column restarts 已啟動後才批次生成
候選；便宜 prescreen 先看 HPWL proxy、重疊比例與估計約束懲罰，只讓較好的少數
候選占用昂貴的 refine workers。提交設定在高權重 tail cases 把 direct-refine 配額
重整為 6 個 slots，並以 4 倍 oversampling 先篩再修；這些 slots 與 column restarts
共用同一個 worker pool 和同一條 deadline，因此增加模型候選不會免費增加總 wall
clock。

這是前後端接縫的核心：前端提供「可能有用的幾何與拓撲偏置」，後端決定該偏置
能否在合法化後留下。Raw overlap、raw area 或 raw HPWL 只用於候選供給，不是最終
晉級證據。

## 5. Candidate portfolio：不押單一路徑

每個 case 的名目預算依 block count 指數成長：

```text
budget(n) = clamp(8.498×10⁻⁵ · exp(n/12), 0.05, 1.22) seconds
```

這個曲線刻意跟官方 case 權重的 `exp(n/12)` 同形：小 case 快速交卷，把時間留給
對總分影響最大的 tail cases。實際 full-100 平均 runtime 是 `0.299 s/case`，最大
case 加上 sampling、selection 與 post-pass 後為 `1.803 s`。

Column portfolio 不是單純換 random seed。各 restart 同時改變：

- column 數量與 normal/transposed orientation；
- frame height 與由 preplaced boundary tags 推回的候選 frame；
- 一般或 violation-averse 的搜索權重；
- unit 的 column assignment、column order 與 subgroup order。

同一時間窗中，一部分 workers 探索不同 column 拓撲，另一部分 workers 把
direct/flow 候選放進同一個 legalize–refine consumer。最後所有候選回到相同的
HPWL／area／soft-violation 座標系比較。這比「先跑完整模型、再串行跑完整合法化」
更適合 deadline：GPU sampling latency 與 CPU restart 搜索大部分重疊。

## 6. Column-slicing 建構式合法化

Column arm 是後端的安全底座，也是學習式候選的共同 legalizer。流程如下：

```text
矩形候選 + 約束
    ↓ 解析 soft / fixed / locked，統一 MIB shape
placement units（cluster / soft-MIB 合併）
    ↓ 選 frame、column 數與 orientation
在 locked obstacles 周圍逐 column 堆疊 units
    ↓ soft shape 由面積與 band width 解析
合法矩形版圖
    ↓ simulated annealing 改 column / order / subgroup
多個合法 column candidates
```

每次 layout evaluation 都重新由 column 結構生成矩形，不是在現有座標上任意推開
重疊。Locked blocks 先成為障礙物；units 再在可用 bands 中由下往上或由上往下
堆疊。Soft block 的另一邊長由目標面積除以 band width 得到，因此搜索主要發生在
離散的 column 拓撲與順序，而非不受控的連續座標空間。

SA 使用與官方 no-runtime 成本同形的內部目標：

```text
proxy = (1 + 0.5·(HPWL_proxy_gap + max(0, Area_proxy_gap)))
        × exp(2·w_v·V/N_soft)
```

不同 restart 可暫時使用較大的 `w_v` 尋找低違規 basin，但跨 restart 選解時一律
回到相同權重。若平行 pool、模型或精修發生例外，求解器會退回 sequential column
path；最外層仍保留一個把所有非預置 block 排成單列的 guaranteed-feasible fallback。

---

## 7. 從合法化到精修：每一步都可退回

Direct/flow 候選的 `refine_prediction` 不是單次推開，而是一條有結構的 pipeline：

1. 統一 MIB 成員形狀，保留 fixed/preplaced 尺寸。
2. 從 boundary tags 推回 frame，先把 tagged blocks 對齊對應牆。
3. 在緊 frame 中做 min-displacement legalization；提交版把第一個 frame 的面積尺度
   從歷史的 `1.08 × area_ref` 收到 `1.02 × area_ref`。
4. 重建 cluster 的接觸關係。
5. 在目前 separation DAG 內做 continuous/discrete moves、shape squeeze 與 HPWL
   refinement。

候選仲裁後還有四個短 post-passes：

- **coordinate polish**：在既有 separation DAG 上聯合重解兩個軸，只接受完整 proxy
  嚴格改善且 hard guards 通過的結果；
- **final edge seating**：把仍可達的 boundary blocks 貼到最後外框，只接受軟違規
  嚴格下降；
- **tag compression**：沿 separation DAG 把整條 movable chain 向 preplaced tag line
  單向壓縮，重查 overlap、shape 與官方形式的 soft violations；
- **grouping bridge**：只對仍有 grouping violation 的版圖做 20 ms 有界修復，必須讓
  grouping、總 soft violations 與 proxy 同時改善才提交。

所有這些 pass 都是 pure-or-revert：失敗、超時、數值異常或 guard 不過就回傳輸入
版圖。泛用但昂貴的 violation-killer 在最終包中反而關閉；我們只保留有量測支持、
可在 0.3 秒操作點內承重的外科 pass。

## 8. Legality 是准入條件，proxy 才是排序條件

後端有兩層排序，不能混在一起：

### 8.1 Raw prescreen

只用來決定哪些模型樣本值得花 refine slot。它看 HPWL proxy、overlap fraction 與
constraint penalties，但不宣稱能預測最終官方分數。

### 8.2 Legal candidate selection

Column 與 refined direct/flow candidates 用同一個 evaluator-form proxy：

```text
rank(P) = (1 + 0.5·((HPWL(P)−HPWL_ref)/HPWL_ref
                    + max(0, Area(P)/Area_ref−1)))
          × exp(2·V(P)/N_soft)
```

`HPWL_ref` 取本次 candidate pool 的最小 HPWL，`Area_ref` 以約 97% 利用率估計；
求解時不知道 golden denominator，所以這只是同 case 的排序器，不等同官方成本。
為避免 proxy noise 讓模型候選以極小差距換掉穩定的 column 解，direct/flow candidate
必須比 column champion 至少好 `1.5%` 才能切換。

Legality 不放在這個公式裡交易。Refiner 沒有產生合法結果就不進池；選到模型候選後
還會再做一次 overlap repair/check；末端 pass 也各自重查 locked、fixed、soft area
與 overlap。這個「准入後才排序」的分層，是 100/100 feasibility 的主要來源。

## 9. 後端的實測品質

最終 grouping-bridge 提交包從全新目錄解壓後跑 official100：

| 指標 | 結果 | 口徑 |
| --- | ---: | --- |
| `total_score_no_runtime` | **1.1437** | 官方 case 權重，runtime 固定為 1 |
| hard feasibility | **100/100** | 0 overlap / area / fixed / preplaced hard violations |
| 平均 / 中位 runtime | **0.299 / 0.063 s** | evaluator 實測 wall clock |
| P90 / 最大 runtime | **1.028 / 1.803 s** | evaluator 實測 wall clock |
| weighted HPWL gap | **0.114** | 依 `exp(n/12)` 加權 |
| weighted area gap | **0.049** | 依 `exp(n/12)` 加權 |
| weighted `V_rel` | **0.027** | 依 `exp(n/12)` 加權 |
| weighted utilization | **92.2%** | `Σblock area / bbox area`，依 `exp(n/12)` 加權 |

後端架構演進的量級也很清楚：早期 v5 Anchor-GNN + repair 是 `2.1158`；換成
column backbone + refiner 後進到 `1.238–1.246`；最終低延遲候選組合與末端外科
修復則到 `1.1437`。這些是不同時期的 sealed operating points，足以顯示架構級
進步，但小差值仍只以同 session paired runs 判定，不拿跨期絕對值做 ablation。

### 一個機制轉移

前端報告完成時，合法化造成的面積膨脹是最大損失。最終提交包的 weighted area gap
已降到 `0.049`，而 weighted HPWL gap 是 `0.114`。也就是說，後端已把「塞得下」
大致解掉，剩餘難題主要是**哪個 block 應該在哪一個 column、哪一段接觸鏈中**；
固定拓撲內的小幅座標 polish 已不再有足夠餘量。

## 10. 我們試過並被自己的量測否定的方向

### 10.1 把更好的座標直接當 column seed —— 幾乎無效

把 golden coordinates 當 seed，結果 `1.2392`，heuristic seed 是 `1.2403`；真實
diffusion checkpoint 當 seed 是 `1.2418`，heuristic 對照是 `1.2400`，都在 SA run
noise 內。原因是舊 seed channel 只以 `x/y` 排序影響初始 columns，time-bounded SA
很快洗掉這個順序。

這不代表模型無用，而是說模型不能只當「比較漂亮的初始座標」。最終設計讓
direct/flow candidates 各自完成合法化與精修，再與 column champion 競爭，才能保留
模型輸出的結構差異。

### 10.2 把 raw overlap 做得更低 —— 指標改善、端到端反而退化

Physics guidance 讓 raw overlap 在 7 個 probe cases 降低 30–90%，full-100 卻從
`1.1363` 退化到 `1.1433`（`+0.0070`）。更激進的 noise optimization 讓內部能量
下降 28%，但 full-100 no-runtime 從約 `1.1539` 退化到 `1.2714`，runtime 也約加倍。

兩者的共同死因是：refiner 本來就能消化淺重疊；先把候選全部推成相似的「近合法」
幾何，反而犧牲 best-of-N 所需的拓撲多樣性。Raw legality 不是當時的稀缺資源。

### 10.3 候選越多越好 —— 錯

把 direct refine slots 與 oversampling 從已驗證甜蜜點繼續放大，128-sample GPU batch
拖延所有 refine workers，full-100 退化 `+0.0706`。另一條 Retrieval R4 路線在固定
容量內強制用兩個 transferred candidates 取代 direct candidates，也讓 no-runtime
從 `1.1258` 退化到 `1.1329`（`+0.0071`），runtime 沒有補償收益。

真正重要的是「在 deadline 前完成精修的有效候選數」，不是 raw sample count。

### 10.4 用更重的精確修復收尾 —— 有品質，但時間前緣不成立

對 `n ≥ 100` 的 21 個 cases 使用 SciPy LP joint repair，可把 no-runtime 從
`1.1530` 降到 `1.1421`，但額外花 `99.8 s/100 cases`，推算平均 runtime 從
`0.290 s` 升到 `1.288 s`。即使只選收益最大的單一 case，平均 runtime 也會超過
`0.3 s` 目標。

因此我們沒有把它塞進 submission，而是抽出廉價的 grouping bridge：只做能在 20 ms
內完成、且有嚴格 monotone guards 的那一小段機制。

## 11. 給交換對象的三個要點

1. **合法性最好來自表示法與建構過程。** 把 cluster/MIB 變成 units、把 locked blocks
   變成 obstacles、由 area 解析 shape，比在任意座標上反覆加 overlap penalty 穩定。

2. **候選生成與合法化必須共同排程。** GPU sampling 與 CPU restarts 重疊，refine
   slots 是固定容量；候選數、候選多樣性與每個候選能拿到的修復時間必須一起調。

3. **Proxy 只負責同 case 選解，晉級仍看 evaluator。** Golden denominator 在 solve
   時未知，deadline-SA 又有可見方差；我們用 evaluator-form proxy 降低錯選，再用
   contemporaneous paired full-100 runs 決定是否促轉。

| | |
| --- | ---: |
| official100 no-runtime | **1.1437** |
| hard feasibility | **100/100** |
| weighted utilization | **92.2%**（黃金約 97.1%） |
| weighted area gap / HPWL gap | **0.049 / 0.114** |
| weighted `V_rel` | **0.027** |
| 平均 / 最大 runtime | **0.299 / 1.803 s** |

後端已經能在很短的平均時間內穩定交出合法解，並把早期 legalizer 的面積磨損大幅
壓低。剩餘缺口不是再做一次更細的座標微調，而是 topology：column assignment、
column order、group contact structure 與模型候選如何在合法化後保留。這也是我們對
前後端接縫的最終結論：**更好的 raw geometry 只有在後端能保留其拓撲差異時才有價值。**

數字邊界：本報告的最終表格來自 `2026-08-12` grouping-bridge 提交包的 fresh-extract
official100；歷史 ablation 使用各自文件記錄的同時段 paired runs。官方 runtime
factor 仍取決於其他隊伍的 case median，本地 no-runtime 與 wall-clock 不能直接替代
最終 leaderboard score。
