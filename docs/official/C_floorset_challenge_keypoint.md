# FloorSet Challenge: 數據驅動的 SoC 平面規劃

## 1. 背景與動機 (Background & Motivation)
固定的 SoC 平面規劃是一個高度複雜的 NP 完全問題，多維度的限制條件使其難以快速收斂。本競賽的目標是透過機器學習 (ML) 的引導，將過去耗費數天的手動迭代設計，轉變為幾分鐘內即可完成的自動化流程。為了解決 ML 缺乏高保真訓練資料的問題，主辦方釋出了基於真實工業場景的 FloorSet 資料集。

## 2. 相關研究與概念驗證 (Related Work & Proof of Concept)
過去的傳統基準測試（如 MCNC、GSRC）缺乏真實的最佳解，且未能將多種限制條件整合為全面的設計問題。FloorSet 透過反向工程提供了數百萬個確保面積與線長最佳化的佈局方案。實驗證明，傳統啟發式方法（如模擬退火）在處理中型設計時容易超時且存在誤差，而 ML 模型（如擴散模型）能在不到一分鐘內產出高品質解。

## 3. 問題陳述 (Problem Statement)
* **輸入條件**：包含區塊的面積目標、固定的外部終端位置，以及模組間的連線權重矩陣。
* **軟限制 (Soft Constraints)**：包含群組相鄰、相同尺寸的多次實例化區塊 (MIB)、邊界要求、預先放置及固定形狀區塊。違反軟限制會遭受扣分懲罰。
* **硬限制 (Hard Constraints)**：軟體區塊的面積誤差不得超過 1%，且區塊之間絕對不可重疊。違反任何硬限制會直接被判定為不可行解。
* **輸出要求**：提供所有區塊無重疊的左下角座標 (x, y) 以及寬度與高度 (w, h)。

## 4. 目標函數與總分 (Objective Function & Total Score)
* **單一案例成本**：成本公式結合了線長差距、面積差距、軟限制違規的「指數型懲罰」，以及執行時間係數。分數越低越好。
* **違規懲罰**：不可行解會得到一個極大的固定懲罰分數（$M=10$）。
* **總分計算**：整體競賽的總分是 100 個隱藏測試案例的加權平均，其中大型測試案例（區塊較多）的權重會呈指數級別放大，這意味著在大型設計上失敗會受到極嚴重的懲罰。

## 5. 資料集與激勵 ML 解決方案 (Dataset & Incentivizing ML)
* **FloorSet-Lite 資料集**：提供 100 萬個訓練樣本、100 個驗證樣本，以及 100 個隱藏的測試樣本。
* **激勵機制**：競賽透過將「執行時間」納入計分，並給予大型案例極高的權重，強烈懲罰規模擴展性差的傳統演算法。這項設計旨在鼓勵參賽者開發能快速推廣並解決大型佈局問題的資料驅動 ML 模型。
